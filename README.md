# Portfolio Niko Dwicahyo Widiyanto

Personal portfolio website built with React and Supabase, featuring a public-facing site and an admin dashboard.

**Live Demo:** [nikodwicahyo.vercel.app](https://nikodwicahyo.vercel.app)

---

## Tech Stack

- **ReactJS** — Frontend framework
- **Tailwind CSS** — Utility-first CSS framework
- **Supabase** — Backend (database, auth, storage, realtime)
- **Framer Motion** — Animation library (page transitions)
- **AOS** — Animate On Scroll library
- **React Router** — Client-side routing
- **React Helmet Async** — SEO & meta tags
- **Lucide** — Icon library
- **Material UI** — React component library (tabbed portfolio)
- **SweetAlert2** — Alert dialogs
- **React Hook Form** — Form validation
- **Axios** — HTTP client
- **PDF.js** — PDF thumbnail rendering

---

## User Roles

| Role | Access |
|---|---|
| **Visitor (Public)** | View projects, certificates, experiences — leave a comment |
| **Admin** | Login to dashboard — full CRUD on projects, certificates, experiences, tech stacks, CV — manage comments |

## Getting Started

### Prerequisites

- Node.js `>= 22.x` (required by `pdfjs-dist@6`)
- npm or yarn

### 1. Clone & Install

```bash
git clone https://github.com/nikodwicahyo/portofolio.git
cd portofolio
npm install
```

> If you encounter peer dependency issues: `npm install --legacy-peer-deps`

### 2. Environment Variables

Create a `.env` file in the root directory:

```env
VITE_SUPABASE_URL=your-supabase-project-url
VITE_SUPABASE_ANON_KEY=your-supabase-anon-key
VITE_FORMLY_ACCESS_KEY=your-formly-access-key
```

> Find Supabase keys in your project under **Settings → API**.  
> ⚠️ Never commit `.env` to version control.

### 3. Supabase Client (`src/supabase.js`)

```javascript
import { createClient } from '@supabase/supabase-js'

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY

if (!supabaseUrl || !supabaseKey) {
  throw new Error('Supabase credentials missing. Check your .env file.')
}

export const supabase = createClient(supabaseUrl, supabaseKey)
```

### 4. Database Setup

Go to your Supabase project → **SQL Editor** → run the script below (run once):

```sql
-- ============================
-- TABLES
-- ============================
CREATE TABLE public.projects (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text,
  description text,
  img text,
  link text,
  github text,
  features jsonb,
  tech_stack jsonb,
  is_published boolean DEFAULT true,
  order_index int DEFAULT 0,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE public.certificates (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  img text,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE public.portfolio_comments (
  id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  content text NOT NULL,
  user_name text NOT NULL,
  profile_image text,
  is_pinned boolean DEFAULT false,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE public.experiences (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  position text,
  company text,
  description text,
  start_date date,
  end_date date,
  logo_url text,
  location text,
  employment_type text,
  skills text[],
  created_at timestamptz DEFAULT now()
);

CREATE TABLE public.tech_stacks (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text,
  icon text,
  display_order int DEFAULT 0,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE public.cv_documents (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  filename text,
  file_data text,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

CREATE TABLE public.profiles (
  id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  username text UNIQUE NOT NULL,
  role text NOT NULL CHECK (role IN ('admin', 'user')),
  created_at timestamptz DEFAULT now()
);

-- ============================
-- RLS
-- ============================
ALTER TABLE public.projects ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.certificates ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.portfolio_comments ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.experiences ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.tech_stacks ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.cv_documents ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "public read projects"
ON public.projects FOR SELECT USING (true);

CREATE POLICY "public read certificates"
ON public.certificates FOR SELECT USING (true);

CREATE POLICY "public read comments"
ON public.portfolio_comments FOR SELECT USING (true);

-- Comments are written only by the submit-comment edge function (service_role).
-- Do NOT add an anon INSERT policy: it bypasses the rate limit, length caps and
-- server timestamp. See supabase/migrations/20261022_security_hardening.sql.

CREATE POLICY "public read experiences"
ON public.experiences FOR SELECT USING (true);

CREATE POLICY "public read tech_stacks"
ON public.tech_stacks FOR SELECT USING (true);

CREATE POLICY "public read cv_documents"
ON public.cv_documents FOR SELECT USING (true);

CREATE POLICY "admin manage projects"
ON public.projects FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "admin manage certificates"
ON public.certificates FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "admin manage comments"
ON public.portfolio_comments FOR UPDATE, DELETE
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "admin manage experiences"
ON public.experiences FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "admin manage tech_stacks"
ON public.tech_stacks FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "admin manage cv_documents"
ON public.cv_documents FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

-- ============================
-- STORAGE
-- ============================
INSERT INTO storage.buckets (id, name, public)
VALUES ('project-images', 'project-images', true)
ON CONFLICT DO NOTHING;

CREATE POLICY "admin upload project images"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'project-images'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "public read project images"
ON storage.objects FOR SELECT
USING (bucket_id = 'project-images');

INSERT INTO storage.buckets (id, name, public)
VALUES ('certificate-images', 'certificate-images', true)
ON CONFLICT DO NOTHING;

CREATE POLICY "admin upload certificate images"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'certificate-images'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "public read certificate images"
ON storage.objects FOR SELECT
USING (bucket_id = 'certificate-images');

-- Sanitized SVG tech-stack icons (sanitized client-side, written directly;
-- dashboard never uploads SVG raw). Needs the bucket plus admin policies.
INSERT INTO storage.buckets (id, name, public)
VALUES ('svg-assets', 'svg-assets', true)
ON CONFLICT DO NOTHING;

CREATE POLICY "public read svg assets"
ON storage.objects FOR SELECT
USING (bucket_id = 'svg-assets');

CREATE POLICY "admin upload svg assets"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'svg-assets'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "admin delete svg assets"
ON storage.objects FOR DELETE
USING (
  bucket_id = 'svg-assets'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);
```

### 4b. Enhancement Migration (run once, additive only)

Go to **SQL Editor** → run `supabase/migrations/20261002_portfolio_enhancements.sql`. It adds:
`comment_rate_limits` (edge-function ledger), `portfolio_events` analytics table,
`cv-documents` storage bucket + missing storage UPDATE/DELETE policies, and nullable
showcase columns (`projects.slug/impact`, `experiences.employment_type/skills`,
`certificates.issuer/issued_at/verify_url`).
Then run `supabase/migrations/20261003_experience_logos.sql` for the
`experience-logos` bucket policies (dashboard logo uploads are denied without them).

Finally run `supabase/migrations/20261022_security_hardening.sql` — **after** deploying
the function in 4c, otherwise comments fail in between. It removes the anon INSERT path
on `portfolio_comments` (the only writer is the submit-comment function), pins
server-owned columns, adds DB-level length/flood guards, and makes `profiles.role`
read-only for clients. Re-run it after any schema reset.

Then run `supabase/migrations/20261023_api_hardening.sql`: it revokes anonymous
`SELECT` on `storage.objects` (public URLs keep working, anonymous bucket listing
stops) and restricts public project reads to `is_published` rows.

Finally run `supabase/migrations/20261024_privacy_retention.sql`: it prunes
`comment_rate_limits` after 24h and `portfolio_events` after 30 days (both on
write, no pg_cron), extends the storage-listing lockdown to signed-in non-admins
(previously `anon` only), and sets per-bucket size / MIME limits so the
attacker-controlled `file.type` and `file.size` are enforced by Storage itself.

Then run `supabase/migrations/20261025_comment_markup.sql`: comments are plain
text, and it adds a `comment_no_markup` CHECK so the table itself refuses
tag-like content and `javascript:` / `data:` URLs — even for `service_role` or
any future write path that skips the shared filter in
`supabase/functions/submit-comment/rules.mjs`.

Comments are written only by the edge function, so the database does not need an
`anon` INSERT policy; do not add one back.

### 4c. Deploy the comment function (required)

The comment form posts to the `submit-comment` edge function and has no direct-insert
fallback, so comments fail until it is deployed:

```bash
supabase secrets set COMMENT_HASH_SALT="$(openssl rand -hex 32)"   # recommended
# optional — enables the CAPTCHA. Pair with VITE_TURNSTILE_SITE_KEY or every
# comment will be rejected:
# supabase secrets set TURNSTILE_SECRET=<cloudflare-turnstile-secret>
supabase functions deploy submit-comment
```

`COMMENT_HASH_SALT` peppers the hashed IP in `comment_rate_limits`. Without it
the function falls back to the service-role key as the pepper (still secret, but
rotating it resets every rate-limit bucket). Rotating `COMMENT_HASH_SALT` is the
intended way to invalidate all stored buckets.

`TURNSTILE_SECRET` is the only control that stops a scripted sender from
spoofing `X-Forwarded-For` to mint fresh rate-limit buckets. Without it the
per-IP limit is best-effort and the DB-level 30/min global cap is the backstop
(which also means one attacker can briefly block everyone).

`verify_jwt` is false for this function (`supabase/config.toml`) because the browser
preflight is unauthenticated; the rate limit, length caps and input filter live inside
the function, and the database no longer accepts client inserts.

The comment rules — length caps, tag/markup rejection, link cap — live once in
`supabase/functions/submit-comment/rules.mjs`. The edge function, the browser form
and the DB constraint in `20261025_comment_markup.sql` all enforce that one
definition; `npm test` covers it. Do not re-add a hand-copied regex anywhere.

### 4d. Close signups

The site has no signup UI; the only accounts are admins created manually. In
**Authentication → Providers → Email**, disable "Allow new users to sign up"
(`supabase/config.toml` already sets it for local dev). Then verify the whole
anonymous surface — comment writes, internal tables, storage listing, public file
serving and the signup toggle:

```bash
npm run check-api
npm run check-api -- --xff   # also probes the X-Forwarded-For rate-limit assumption
```

`--xff` creates one comment when the per-IP limit works (the id is printed so you
can delete it), which is why it is opt-in.

### 5. Enable Realtime (Comments)

Go to **Table Editor → portfolio_comments → Enable Realtime**.

### 6. Create Admin Account

**Step 1** — Go to **Authentication → Users → Add User** in Supabase Dashboard, then copy the generated User ID.

**Step 2** — Run this in the SQL Editor (replace `USER_UUID` with the copied ID):

```sql
INSERT INTO public.profiles (id, username, role)
VALUES ('USER_UUID', 'admin', 'admin');
```

### 7. Run Locally

```bash
npm run dev
```

Open `http://localhost:5173` in your browser.

## Pages & Features

### Public (Visitor)
- **Home** — Hero section with typing effect, CTA buttons, social links
- **About** — Profile, quote, stats (projects, certificates, experience years), CV viewer
- **Projects** — List of published projects with detail modal/page
- **Certificates** — Certificate gallery
- **Comments** — View all comments, submit a new comment with name and optional profile photo
- **Contact** — Contact form (via Formly API), comment section, social links

### Admin (Dashboard)
- **Login Page** — Email & password authentication via Supabase Auth
- **Dashboard** — Navigable sidebar with sections
- **Projects** — Create, edit, delete projects; manage image, links, features, tech stack, publish status, and order
- **Experiences** — CRUD for work experience entries (title, company, dates, description, logo, location)
- **Certificates** — Upload and delete certificate images
- **CV Documents** — Upload, activate/deactivate, preview, and delete CV PDFs
- **Tech Stacks** — CRUD for tech stack items (name, image, category)
- **Comments** — View all comments; pin/unpin for highlighting; delete inappropriate comments

## Troubleshooting

- Ensure Node.js is installed and you're in the correct directory.
- Double-check your `.env` values and restart the dev server after changes.
- If RLS is blocking requests, verify the `profiles` row exists for your admin user.
- Clear browser cache if you see stale data.
